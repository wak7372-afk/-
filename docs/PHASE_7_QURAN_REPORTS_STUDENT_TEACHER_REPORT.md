# تقرير المرحلة السابعة: تشغيل التقارير القرآنية

## نطاق المرحلة

تم بناء المسار التشغيلي اليومي لتقارير الحفظ والتثبيت والمراجعة، ابتداءً من عرض التقرير للطالب وانتهاءً بمتابعة المعلم وقرارات التمديد والإعفاء.

## القواعد المعتمدة

- التقرير يومي ونافذته من `00:00` إلى `23:00` بتوقيت مسقط.
- نقاط الحفظ `4`، والتثبيت `3`، والمراجعة `3`، دون إعادة توزيع النوع غير الموجود.
- تنخفض النقاط خطياً حتى نهاية المهلة وتحفظ بدقة منزلتين عشريتين عند الإنجاز.
- لا يستطيع الطالب الإنجاز قبل بداية التقرير.
- يمنع التقرير المتأخر غير المنجز الطالب من إنجاز التقارير اللاحقة حتى ينجزه أو يعفيه المعلم.
- يصنف الإنجاز إلى مبكر، وفي الوقت، وقرب النهاية، ومتأخر بعد انتهاء المهلة.
- التمديد يعيد توزيع انخفاض النقاط حتى المهلة الجديدة.
- طلب التمديد يقبل تقريراً واحداً أو عدة تقارير، ومدة الطلب القصوى `72` ساعة.
- يستطيع المعلم قبول بعض بنود الطلب ورفض بعضها، واختيار مدة أو وقت انتهاء محدد.
- إذا صدر القرار قبل انتهاء المهلة يبدأ التمديد بعدها، وإذا صدر بعدها يبدأ من وقت القرار.
- المعلم المسؤول والمدير يملكان الصلاحية الكاملة، والمعلم المساعد يحتاج صلاحية مراجعة مفوضة.

## قاعدة البيانات

أضيفت الهجرة `0017_quran_report_operations.sql` وتشمل:

- تغذية تقارير الطالب المحمية.
- إنجاز التقرير وحساب النقاط والتصنيف على الخادم.
- منع تجاوز تقرير قديم متأخر.
- إنشاء طلب تمديد متعدد التقارير.
- لوحة محاسبة المعلم وسجل الطالب الكامل.
- قائمة طلبات التمديد والقرارات الجزئية.
- إعفاء الطالب مع حفظ السبب.
- أحداث غير قابلة للتعديل وسجل تدقيق وإشعارات مرتبطة بالقرارات.
- سحب التنفيذ من `public` ومنحه للمستخدمين الموثقين فقط.

## واجهة الطالب

- صفحة مستقلة للتقارير في `student/reports.html`.
- شريط سبعة أيام وملخص الإنجاز والتأخير والنقاط.
- بطاقة مستقلة لكل من الحفظ والتثبيت والمراجعة.
- عرض حي للنقاط المتوقعة ونسبة الاستحقاق والوقت المتبقي.
- حالات واضحة للإنجاز، والتأخير، والإعفاء، والانتظار، والحجب.
- اختيار تقرير واحد أو عدة تقارير وطلب تمديد مع المدة والسبب.
- ربط صفحة التقارير بقائمة لوحة الطالب المكتبية وقائمة الهاتف.

## واجهة المعلم

- تبويب إنشاء التقارير ورفع ملف Excel المعتمد في المرحلة السابقة.
- تبويب محاسبة الطلاب حسب اليوم مع ملخص الحالات.
- عرض حالة الحفظ والتثبيت والمراجعة لكل طالب وعدد مهامه الفائتة.
- سجل كامل للطالب يبين وقت الإنجاز والتصنيف والنقاط والإعفاءات.
- قرار إعفاء موثق يزيل الحجب الناتج عن التقرير المتأخر.
- قائمة طلبات تمديد تسمح بالقرار على كل تقرير داخل الطلب.
- دعم التمديد بالمدة أو بوقت انتهاء محدد.
- تصميم متجاوب؛ تتحول صفوف المحاسبة والسجل إلى بطاقات واضحة على الهاتف بلا تمرير أفقي.

## التحقق المنفذ

- نجحت إعادة بناء Supabase المحلية وتطبيق الهجرات من `0001` إلى `0017`.
- نجح اختبار SQL التشغيلي داخل Docker، ويغطي المنع والتمديد والإنجاز والإعفاء والصلاحيات.
- نجحت اختبارات Node الكاملة: `55/55`.
- نجح `git diff --check` دون أخطاء تنسيق؛ ظهرت تنبيهات تحويل نهايات الأسطر فقط.
- اختبرت رحلة الطالب في المتصفح: تقرير قديم متأخر، فك الحجب بعد الإنجاز، وطلب تمديد متعدد التقارير.
- اختبرت رحلة المعلم في المتصفح: المحاسبة، السجل، الإعفاء، والقبول الجزئي لطلب التمديد.
- اختبرت واجهتا الطالب والمعلم على شاشة هاتف `390x844` دون تجاوز أفقي للصفحة.
- تعذر إعادة تشغيل `supabase db lint` في جلسة الطرفية الحالية لعدم توفر Supabase CLI، مع نجاح إعادة بناء القاعدة واختبار SQL الفعلي قبل تعديل CSS المتجاوب.

## خارج هذه المرحلة

- تشغيل الوظيفة المجدولة ومراقبتها في بيئة الإنتاج.
- تطبيق الهجرات الجديدة على مشروع Supabase المنشور.
- نشر الواجهة المحدثة على Vercel وإجراء اختبار قبول بالإنتاج.
