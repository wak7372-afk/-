1. نسخة مخطط `schema.sql`.
2. نسخة بيانات `data.sql` بصيغة قابلة للاستعادة.
3. حفظ النسختين خارج Git وعدم رفع بيانات المستخدمين إلى مستودع عام.
4. تسجيل وقت النسخ وإصدار Postgres ومشروع المصدر.
5. فحص أن الملفين غير فارغين ويحتوي المخطط على الجداول الأساسية.

## الخيار المحلي الموصى به

تثبيت Docker Desktop ثم استخدام Supabase CLI المرتبط بالمشروع لإنشاء نسخ المخطط والبيانات. تحفظ الملفات مؤقتا في `scratch/backups` المستبعد من Git، ثم تنقل إلى موقع خاص وآمن.

## الخيار المستمر للإنتاج

استخدام خطة Supabase توفر نسخا يومية، أو إعداد نسخة دورية مشفرة في مخزن خاص. النسخة الدورية لا تلغي ضرورة اختبار الاستعادة.

## قاعدة الرجوع لكل Migration

- تكون Migration إضافية وتوافقية ولا تحذف الجداول القديمة في الدفعة الأولى.
- يوثق لكل تغيير SQL رجوع معاكس أو طريقة تعطيل الميزة.
- عند فشل التطبيق يوقف النشر، ولا تعاد المحاولة قبل تحليل السجل.
- لا تستعاد قاعدة الإنتاج إلا بقرار صريح وبعد تحديد نقطة الاستعادة وفترة التوقف.
