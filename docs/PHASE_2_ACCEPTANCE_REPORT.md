# تقرير قبول المرحلة الثانية

التاريخ: 2026-08-09
الحالة: مكتملة تقنيا، بانتظار اعتماد مالك المشروع.
لم تطبق Migration `0011` على Supabase الإنتاجي.

## المخرجات

- Migration توافقية: `supabase/migrations/0011_learning_circles_core.sql`.
- مخطط وعلاقات: `docs/LEARNING_CIRCLES_DATA_MODEL.md`.
- اختبارات ثابتة: `tests/learning-circles-schema.test.mjs`.
- اختبار قيود سلوكي: `tests/sql/learning_circles_invariants.sql`.
- بيانات قديمة وهمية واختبار نقلها: `tests/sql/legacy_circle_fixture.sql` و`learning_circles_backfill_assertions.sql`.

## ما يضيفه النموذج

1. حلقة موحدة من نوع قرآن أو تعليمية.
2. عدة مواد للحلقة التعليمية.
3. مسؤول واحد ومساعدون متعددون بصلاحيات تفصيلية.
4. عضويات مؤرشفة وقيد يمنع حلقتين قرآن نشطتين لطالب.
5. طلبات نقل يقررها المدير.
6. إعدادات النقاش والتوقيت ونافذة الأعذار.
7. سجل تدقيق عام قابل للتوسع.

## أدلة الاختبار

- أعيد بناء قاعدة Supabase المحلية من `0001` إلى `0011` بنجاح.
- نجح ترحيل حلقة قرآن وفصل تعليمي وعضوياتهما من الجداول القديمة الوهمية.
- احتفظت السجلات المهاجرة بمعرف UUID نفسه.
- رفضت القاعدة مسؤولا نشطا ثانيا للحلقة.
- رفضت القاعدة حلقة قرآن نشطة ثانية للطالب.
- قبلت القاعدة عضويتين تعليميتين نشطتين للطالب.
- اشتق الخادم نوع العضوية من نوع الحلقة وتجاهل القيمة المرسلة من العميل.
- انتهى اختبار البيانات السلوكي بـ`ROLLBACK` ولم يترك بيانات تجريبية.
- نتيجة `supabase db lint --local --level warning`: لا أخطاء أو تحذيرات.
- نتيجة اختبارات Node: 21 ناجحا، صفر فشل.

## أثر الإنتاج المتوقع

- تنشأ سبعة جداول جديدة فقط مع دوال وفهارس ومشغلات مرتبطة بها.
- تنسخ الحلقات الأربع والفصل التعليمي الحالي إلى النموذج الجديد.
- ينشأ المعلم الحالي مسؤولا لكل سجل قديم يملكه.
- لا توجد عضويات طلاب حالية في الجداول القديمة، لذلك لا يوجد تعارض مع قيد القرآن.
- لا تحذف أو تعدل Migration الجداول القديمة، وتبقى الصفحات الحالية مستخدمة لها.
- الجداول الجديدة محمية بـRLS ومغلقة أمام `anon`، ولا تستخدمها الواجهة قبل المرحلة الثالثة.

## خطة الرجوع

قبل انتقال أي صفحة إلى النموذج الجديد، يمكن الرجوع بإزالة الجداول والدوال الجديدة فقط؛ الجداول القديمة لم تتغير. بعد بدء الكتابة في النموذج الجديد يصبح الرجوع ترحيلا منظما لا حذفا مباشرا.

## بوابة المرحلة التالية

تبدأ المرحلة الثالثة بعد اعتماد هذا التقرير، وتركز على دوال الصلاحيات وRLS وعمليات الإدارة الذرية والتحقق الخادمي. تطبيق Migration على الإنتاج لا يتم تلقائيا لمجرد بدء المرحلة الثالثة؛ يسبقه فحص SQL نهائي ونقطة رجوع حديثة.
