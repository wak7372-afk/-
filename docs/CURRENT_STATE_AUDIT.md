# تدقيق الحالة الحالية

التاريخ: 2026-08-09
الحالة: تدقيق أولي لدعم المرحلة صفر، وليس اعتمادا لقاعدة الإنتاج.

## الملخص

- التطبيق موقع ثابت داخل `public` ويستخدم JavaScript وSupabase وينشر على Vercel.
- حالة Git نظيفة على فرع `main` ومتتبعة مع `origin/main`.
- توجد عشر مهاجرات SQL وثلاث Edge Functions، مع اختبارات أمن وسلامة ثابتة.
- نجحت الاختبارات المحلية الثمانية عشر كاملة باستخدام Node المرفق مع Codex.
- لا توجد `.openai/hosting.json`، لذلك المشروع ليس مشروع OpenAI Sites.
- مشروع Vercel `zat-khail` مربوط محليا، وآخر نشر إنتاجي حالته `Ready` على النطاق `zat-khail.vercel.app`.
- مشروع Supabase المرتبط هو `yyqxesnrlgzifydkzkpd` في منطقة `ap-southeast-2`.

## الموجود والقابل لإعادة الاستخدام

- مصادقة محلية باسم المستخدم عبر Edge Function.
- حسابات وأدوار أساسية: مدير، معلم، طالب، ولي أمر.
- جداول أولية للحلقات القرآنية والفصول والطلاب والتقارير والواجبات والاختبارات.
- دالة ذرية `publish_task_batch` لنشر دفعات التقارير القرآنية.
- دالة `get_student_task_feed` تجمع أعمال القرآن والفصول للطالب.
- تخزين خاص لمرفقات تسليم الواجبات وسياسات وصول أولية.
- إشعارات ومحادثات وسجل عمليات مدير واختبارات ضد تسرب الأسرار.
- المهاجرات المحلية `0001` إلى `0010` مطابقة من حيث الإصدارات لسجل المهاجرات البعيد.
- وظائف Supabase الأربع منشورة ونشطة: الدخول باسم المستخدم، استرداد الحساب، إنشاء حساب إداري، وتحليل الجدول.

## الفجوات الحرجة مقارنة بالمواصفات الجديدة

1. `halaqat` و`classrooms` يفترضان `teacher_id` واحدا ولا يدعمان مسؤولا ومساعدين وصلاحيات مفوضة.
2. الحلقة التعليمية ترتبط بمادة واحدة فقط، بينما المطلوب عدة مواد.
3. لا توجد عضوية مؤرشفة أو طلبات نقل أو قيد قاعدة بيانات يمنع حلقتين قرآن نشطتين.
4. لوحة المدير تربط إدارة الحلقات والفصول بصفحات المعلم بدلا من صفحات إدارة مستقلة.
5. تفاصيل الحلقة القرآنية تسمح للمعلم المالك فقط، ولا تعمل للمدير أو المساعد.
6. نموذج التقرير الحالي يدعم حفظا ومراجعة فقط، ولا يدعم التثبيت أو الإصدارات أو الأعذار والتمديدات والحجب.
7. حالة التسليم الحالية `pending/done` غير كافية للحالات الزمنية المطلوبة.
8. موجز الطالب الحالي يمنح نقاطا رقمية رغم أن النظام الجديد لا يعتمد درجات لهذه المهام.
9. واجبات الفصل الحالية نص أو ملف مع درجة، ولا تدعم منشئ الأسئلة أو شروط الإتمام الجديدة.
10. الدردشة الحالية ثنائية مباشرة، لكنها لا تمثل المحادثات والساحات والموضوعات وعضوية الحلقة تمثيلا كافيا.
11. لا توجد وظائف مجدولة للقوائم النهائية الصباحية والمسائية.
12. بعض منطق التوقيت والحالة ينفذ في المتصفح، والمطلوب نقله إلى الخادم.

## مخاطر يجب منعها

- تعديل الجداول القديمة مباشرة قد يكسر الصفحات الحالية؛ يلزم Migration توافقية ثم نقل تدريجي.
- إعادة استخدام حقل `grade` أو `points` سيخالف قرار عدم استخدام الدرجات.
- الاعتماد على `teacher_id` في سياسات RLS يمنع المساعدين ويخلط دور المدير بالمعلم.
- حذف العضوية عند النقل يفقد التاريخ؛ يجب تحويلها إلى عضوية ذات حالة وتواريخ.
- إنشاء التقارير قبل تثبيت محرك الوقت سيولد حالات متناقضة يصعب تصحيحها لاحقا.
- لا توجد حاليا نسخ Supabase في قائمة النسخ الفيزيائية وPITR غير مفعل؛ لذلك يمنع دفع Migration جديدة قبل إنشاء نسخة منطقية قابلة للاستعادة.
