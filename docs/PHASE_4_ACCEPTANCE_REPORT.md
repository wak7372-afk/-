# تقرير قبول المرحلة الرابعة

التاريخ: 2026-08-09
الحالة: مطبقة ومتحقق منها على الإنتاج، بانتظار اعتماد المالك للانتقال إلى المرحلة الخامسة.
النطاق: واجهة المدير لإدارة الحلقات والعضويات وطلبات النقل.

## ما تم بناؤه

1. قسم موحد باسم **إدارة الحلقات** داخل لوحة المدير، دون نقل المدير إلى صفحات المعلم.
2. مؤشرات للحلقات النشطة والقرآنية والتعليمية وطلبات النقل المعلقة.
3. بحث وتصفية بحسب الاسم والمعلم والنوع والحالة.
4. إنشاء حلقة قرآنية أو تعليمية مع المسؤول والوصف والمواد المتعددة.
5. تعديل اسم الحلقة ووصفها وموادها عبر عملية خادمية مدققة.
6. تعيين مسؤول واحد وإضافة عدة مساعدين وإنهاء تكليفهم.
7. صلاحيات مستقلة للمساعد: الإعلانات، Meet، المهام، التسليمات، النقاشات، ومتابعة الطلاب.
8. إضافة الطلاب وإخراجهم مع بقاء سجل العضوية.
9. إنشاء طلب نقل تلقائي عند محاولة ربط الطالب بحلقة قرآن ثانية.
10. شاشة قرار النقل تعرض الطالب والحلقة السابقة والجديدة وتدعم الاعتماد أو الرفض والملاحظات.
11. حفظ رابط Google Meet بعد التحقق من النطاق.
12. أرشفة الحلقة مع إنهاء العلاقات النشطة وإلغاء طلباتها المعلقة.
13. سجل عمليات خاص بكل حلقة وغير قابل للتعديل.

## عقد الخادم الجديد

Migration: `0013_learning_circle_admin_operations.sql`.

- `update_learning_circle_details`: للمدير النشط فقط، ويحدّث البيانات والمواد في معاملة واحدة.
- `end_learning_circle_membership`: للمدير أو المسؤول، وينهي العضوية ويلغي طلب النقل المرتبط عند الحاجة.
- جميع العمليات الحساسة تسجل في `platform_audit_events`.
- لا توجد منح كتابة مباشرة على جداول الحلقات.
- أضيفت قراءة مصادق عليها لجدول `subjects` المرجعي لتفعيل سياسة RLS الموجودة فعلاً.

- تدفق أمان الحلقات الكامل السابق بعد `0013`: ناجح مع `ROLLBACK`.

- فحص النقل: إنشاء الطلب واعتماده ونقل العضوية وإغلاق الطلب.
